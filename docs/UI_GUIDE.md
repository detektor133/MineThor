# Гайд по UI второго экрана

## Принципы
1. Выглядит как Minecraft: ванильные GUI-текстуры, пиксельный шрифт, 9-slice панели, ванильные звуки/цвета выделения.
2. Пиксель-перфект: целочисленный масштаб (`unit` = целое), `filterBitmap=false`, позиции округлены. Дробный апскейл даёт «кривое».
3. Ресурспак/текстурпак — **проверено 2026-10-16, частично**: иконки предметов рендерятся самой игрой (`GuiGraphics.renderItem`, живой `ItemRenderer`), поэтому автоматически подхватывают активный ресурспак — это не наш код, мы просто снимаем то, что игра уже нарисовала. Хром второго экрана (сердца, голод, XP-бар, виджеты, шрифт — `MineThorMinecraftAssets`) **ресурспак не учитывает**, читает прямо из `client.jar` версии. Несогласованность: если у игрока включён текстурпак, иконки предметов будут из пакета, а рамки/сердца — ванильные. Выровнять в Фазе 3 (читать те же текстуры через игру, а не напрямую из jar). Отдельно: запасной вариант нужен, если текстура другой версии лежит по другому пути (пути спрайтов менялись в 1.20.2+).
4. Перерисовка по изменению state. Нет постоянного render loop.
5. Крупные touch-таргеты (минимум ~48dp для навигации; слоты — по сетке, но с отступом на промах пальцем).
6. Тексты — только `strings.xml`.

## Дизайн второго экрана
- Разбить `ThorHudView` (572 строки) на: `Theme/Metrics`, `PanelRenderer` (9-slice), `SlotRenderer`, `HudBarsRenderer`, экранные классы `InventoryScreen`/`MapScreen`/`CraftScreen`/`StatusScreen`.
- Вкладки: Инвентарь · Карта · Крафт · Статус. Внизу/сбоку, не поверх контента.
- Layout вычисляется из размеров дисплея Thor один раз при смене конфигурации; кэшировать `RectF`, не создавать объекты в `onDraw`.
- Состояния: нет подключения / нет маппингов / деградация / ок — отдельные ванильные «пустые» экраны, а не пустота.

## Иконки
Что не так сейчас: снимок фреймбуфера → вырезание чёрного фона flood-fill'ом → обрезка прозрачных краёв → нестабильный размер и рваные края.

Целевой пайплайн:
1. Агент рисует предмет в **offscreen FBO** с `glClearColor(0,0,0,0)` и корректным blend → настоящая альфа.
2. Размер фиксированный (64 или 128 px, степень двойки), без trim — раскладка по слоту делается на Android.
3. Count, durability bar, selection — рисует Android поверх (резкие, не растр из PNG).
4. Передача: батчем, PNG; ключ = `версия|resourcepack-hash|itemId|nbt-hash`.
5. Кэш: память — LRU с лимитом по байтам; диск — файлы по ключу; инвалидация при смене версии/ресурспака.
6. Запрос приоритетом: сначала видимые слоты.
7. Показ: `filterBitmap=false` при целочисленном масштабе; иначе mipmapped bilinear.
8. До 1.20 (нет `GuiGraphics`): отдельный legacy-рендер (`ItemRenderer`/`PoseStack`) либо fallback на текстуру из ассетов для простых предметов.

Контроль качества: набор из ~20 предметов (блок, инструмент, зелье, голова, щит, зачарованный, модовый) — скриншот рядом с ванильным GUI.

## Инвентарь
- Раскладка как ваниле: броня + offhand слева, 27 + хотбар 9, cursor-стак под пальцем.
- Жесты: тап — pickup/place; long-press — тултип (текст приходит из игры, поэтому моды корректны); двойной тап/кнопка — quick-move; кнопка «½» или удержание — split; drag по слотам — раскладка QUICK_CRAFT; drop-зона — выброс.
- Действие → команда с `requestId` + `syncId/stateId`; UI оптимистичный, откат по `REJECTED_STALE_STATE`.
- Кнопки — рядом с жестами, чтобы не нужно было знать жесты.
- Контейнеры (сундук, печь, верстак) — по текущему menu, названия слотов из игры.

## Карта и компас
- Источник: ванильные map-данные (`MapItemSavedData`), уже присутствующие у клиента. Рендер на Android в высоком разрешении, зум/пан.
- Компас: стрелка по yaw (плавная интерполяция), стороны света, цели (spawn/lodestone/death location) если клиенту известны.
- Waypoints: локальные, хранятся по ключу (мир/сервер).
- Minimap по чанкам — только профиль `Extended` для разрешающего сервера.

## Крафт 2x2 («версак»)
- Данные рецептов — из клиента: клиентский `RecipeManager` (≤1.21.1) или recipe book/`RecipeDisplay` (1.21.2+). Это даёт модовые рецепты бесплатно.
- UI: сетка 2x2, результат, список доступных рецептов, «разместить ингредиенты» через штатный `handlePlaceRecipe`.
- Работает только когда открыт инвентарь игрока (Strict).
